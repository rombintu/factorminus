# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [0.1.1] — 2026-11-26

### Надёжность

- `cli`: соединения SQLite и MCP-клиент теперь закрываются (через `contextlib.closing` и context manager); ошибки `sqlite3.Error` печатаются одной строкой без трейсбека.
- `db`: `upsert` проверяет имена таблиц и колонок (`check_identifier`) — защита от SQL-инъекции при попадании внешних данных в ключи; `connect` получил `timeout=30` на случай блокировки базы.
- `mcp`: `Mcp` — context manager (`close`/`__enter__`/`__exit__`), клиент `httpx` освобождается; при HTTP 429 учитывается заголовок `Retry-After` (потолок 5 с, некорректные значения не роняют запрос).
- `iss`: неожиданная структура ответа ISS даёт понятную ошибку «ISS вернул неожиданную структуру ответа» вместо сырого `KeyError`.
- `ingest`: дата «сейчас» для окна загрузки свечей берётся в UTC (`datetime.now(UTC).date()`), а не локальная — окно догрузки больше не сбивается на границе суток.

### Тесты

- `tests/test_db.py` (новый): отклонение инъекции идентификаторов в `upsert`; закреплена семантика «NULL не затирает старое значение».
- `tests/test_mcp.py`: закрытие клиента через context manager; `Retry-After` реально учитывается, мусорный заголовок безопасен.
- `tests/test_cli.py`: ошибка базы печатается одной строкой без трейсбека.
- `tests/conftest.py`: `FakeServer.fail` принимает пары `(код, заголовки)` для проверки Retry-After.

### Известные ограничения (не менялось)

- `.env` перечитывается при каждом `config.get()`; кэш сломал бы изоляцию тестов на `chdir`.
- `load_candles` не пагинирует: при ответе ровно в `limit=2400` свечей данные могут урезаться молча.
- WAL-режим не включён (одиночный писатель, база — кэш).
