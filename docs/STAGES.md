# Журнал этапов

Каждый этап сдаётся PR в `main` с зелёным CI и обновляет свою строку. PR вливается merge-коммитом (не squash): в `main` остаются отдельные коммиты этапа и правок по ревью, на которые ссылается отчёт. Тег `vX.Y.Z` ставит пользователь после merge; по тегу `release.yml` публикует образы и GitHub Release с разделами «Что сделано» из отчётов (этапы и отчёты берутся из этой таблицы). Если несколько этапов сдаются одним PR, у них один релиз: у младшего этапа в колонке «Тег» пишется «в составе `vX.Y.Z`», и в текст релиза идут отчёты всех этих этапов по порядку.

Статусы: `в работе` → `на ревью` (PR открыт) → `принят` (PR влит, тег поставлен). Прямой push в `main` закрыт, поэтому статус «принят» и тег после merge записываются в PR следующего этапа.
