## 4. [Средне] Версии `base.txt` и `dev.txt` никто не сверяет

`check_locks.py` сравнивает только `dev.txt` и `ml.txt`. При этом:
- образ `test` кладёт `venv-dev` поверх venv из `runtime`, поэтому тесты в контейнере идут на версиях `dev.txt`;
- job `test` тоже ставит `dev.txt`;
- образ `runtime` собирается из `base.txt`, и его версии **ни разу не тестируются**. Если они разойдутся (например, после ручного обновления одного файла), numpy в рабочем образе и в тестах будет разный, а тест детерминизма синтетики этого не увидит.

**Что сделать:** `lock-check` сверяет все пары: `base/dev`, `base/ml`, `dev/ml`. Тест на расхождение в `base/dev`.

## 5. [Средне] Dependabot: базовый образ не обновится, pip под вопросом

1. В `Dockerfile` базовый образ задан через `ARG PYTHON_IMAGE=...` + `FROM ${PYTHON_IMAGE}`. Dependabot не обновляет значения `ARG` в `FROM`, поэтому утверждение в `docs/CI.md` «Dependabot обновляет базовый образ» неверно. Сделай литеральный `FROM python:3.12-slim@sha256:... AS base`. `ARG` для переопределения не нужен.
2. Экосистема `pip` на `/` и lock-файлы `uv pip compile` с хэшами и дополнительным индексом torch: Dependabot будет править `requirements/*.txt` по отдельности. Результат либо разойдётся с `uv pip compile` (красный `lockfiles`), либо обновит один файл из трёх (это поймает только правка из п. 4). Надёжнее:
   - убрать `pip` из `dependabot.yml`;
   - добавить `make lock-upgrade` (`uv pip compile --upgrade` для всех файлов + `lock_extra_index.py`);
   - запускать `audit` ещё и по расписанию раз в неделю (новый `schedule` в отдельном маленьком workflow или в `ci.yml`). Тогда уязвимости в закреплённых версиях будут видны без PR.

   В `docs/CI.md`: как обновлять зависимости (`make lock-upgrade` → PR).
3. Frontend `# syntax=...@sha256` и buildkit в `driver-opts` Dependabot тоже не обновит. Это уже записано, оставь.

## 6. [Мелко] Пути и `.env`

1. `.env.example` по-прежнему содержит `FM_DB_PATH=data/fm.sqlite`. Кто скопирует его в `.env` и задаст `FM_DATA_DIR`, получит базу не в `FM_DATA_DIR`, а в `<корень>/data`, без предупреждения. Убери `FM_DB_PATH` из `.env.example`: по умолчанию база и так `<FM_DATA_DIR>/fm.sqlite`. В комментарии оставь, что переменная есть и что относительный путь считается от корня.
2. `load_settings(env=...)` берёт `FM_DATA_DIR` из переданного `env`, а корень — из модульного `REPO_ROOT`, игнорируя `FM_HOME` в том же `env`. Используй `repo_root(env)` для корня, пути `.env` и относительного `FM_DB_PATH`. Тест: `env` с другим `FM_HOME`.
3. `Settings.data_dir` по умолчанию `Path("data")`, то есть относительно текущей папки. Сделай значением по умолчанию `DATA_DIR`.
